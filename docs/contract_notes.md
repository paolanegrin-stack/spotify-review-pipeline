## records.jsonl schema

Exactly one JSON object per original review ID. Final status is completed or
quarantined; pending is internal ingestion state only.

| Field | Type | Allowed values / constraints |
|---|---|---|
| review_id | string | Exact original source ID; unique within the export |
| source_sha256 | string | Lowercase 64-character hexadecimal SHA-256, exactly matching row_sha |
| status | string | completed or quarantined |
| topic | string | Completed only: access, usability, playback, downloads, catalog, billing, support, other |
| intent | string | Completed only: cancellation, complaint, request, praise, unclear |
| sentiment | finite JSON number | Completed only: -1 through 1 inclusive; boolean is invalid |
| severity | integer | Completed only: 1, 2, 3, 4, 5; boolean is invalid |
| entities | array of strings | Completed only: empty array allowed; each present string must be nonblank |
| evidence_quote | string | Completed only: nonblank exact substring of original review_text |
| needs_review | boolean | Completed only: true or false |
| label_config | string | Completed only: nonblank model+prompt+schema-version identifier |
| reason | string | Quarantined only: nonblank; empty text requires empty_review_text |
| cache_source_id | string | Optional completed-record reuse: direct original completed ID with identical text, all classification fields and label_config; source has model-call evidence; no alias chains |

Completed entries require every completed-only field plus review_id,
source_sha256 and status. Quarantined entries require review_id,
source_sha256, status and reason, without invented classifications.
Additional internal fields are not a substitute for this adapter schema.

## Exact hashing implementation

Verbatim contract rule:

The source row hash is SHA-256 of UTF-8 compact JSON of the six original field strings in this order: `review_id, review_text, review_rating, review_likes, app_version, review_timestamp`. Use the provided `row_sha` helper to avoid serialization differences. Do not normalize whitespace or accents.

Verbatim helper implementation from data/check_submission.py:

```python
def canonical(value):
    return json.dumps(value, ensure_ascii=False, separators=(",", ":"), sort_keys=True, allow_nan=False)


def row_sha(row):
    # Strings are preserved exactly; no trimming, translating, or Unicode normalization.
    return hashlib.sha256(canonical([row[k] for k in FIELDS]).encode("utf-8")).hexdigest()
```

FIELDS is the six-field tuple in the contract's order above. File SHA-256
hashes raw file bytes; it is different from each row's source_sha256.
The helper's parsed_rows_sha256 hashes the concatenated binary row digests
in input order (bytes.fromhex for each row digest).
Our text_sha256 hashes the exact original review_text UTF-8 bytes.
Whitespace-only text is empty for quarantine/counting, matching the helper's
not review_text.strip(); trimming is never applied to saved values or hashes.
Missing app_version uses not app_version.strip() for counting only.

## Rules easily missed

- Physical lines are not CSV records: quoted texts may contain newlines.
- Preserve all six source values as strings, including numeric-looking fields.
- Every original ID remains a separate output and aggregate member, even when
  exact text is reused. A text hash is not permission to skip output IDs.
- All 660,622 IDs must be accounted for; 660,609 nonempty texts need semantic
  classification. Empty-text quarantine is not a completed classification.
- Golden human labels must never enter model inputs; their original texts
  still belong to the final corpus. Samples are development checkpoints.
- Stars are metadata, never substitutes for text-based labels.
- No more than 50 reviews per enrichment request; validate every returned ID.
- Resume must add completions without new calls for previously completed IDs
  under unchanged settings. Save both snapshots and a short recording.
- Result caching and provider prompt caching are different; no fictitious calls,
  usage, timing, costs or savings. Failed attempts also belong in call logs.
- Baseline ranking includes only completed complaints/cancellations and uses
  severity_sum, descending, then ascending issue ID. Means use six decimal
  places, decimal half-up rounding. Other numbers are integer strings.
- grading/ingestion.json must be generated by the provided helper; this step's
  run-local reports are not a replacement. Keep self-check outside grading/.
- Missing or unsupported context triggers needs_review, not invented harm.
- Course files contain illustrative prices, not measured costs or current quotes.
- cost/ requires real cold/warm evidence later. This ingestion step does not
  execute a pilot or create fabricated pilot evidence.

## Ingestion implementation notes

src/prepare.py uses only the Python standard library. argparse handles the
required command-line flags; data work uses csv, hashlib, json, sqlite3,
datetime and pathlib. No packages, network access or API keys are needed.
Existing run directories are refused to protect future saved progress.
records preserves every original string and a source_row ordinal; duplicate
IDs can therefore be counted and reported instead of silently overwritten.
distinct_texts is a normalized mapping with one row per nonempty source row;
group by text_sha256 for the corresponding review_ids. All records start with
attempts=0 and status pending, except empty texts which are quarantined.

## 4. Scaling options to consider

- **Batching:** distinguish reading CSV chunks, putting multiple reviews in a request, and a provider's asynchronous Batch API. On restart, load completed work and dispatch pending work. Reconcile uncertain in-flight requests where possible; retrying an unknown outcome may create another charge. Share a global requests/tokens limiter and a single spend ledger across workers. Use bounded retries with backoff and jitter. Reserve estimated worst-case spend for queued/in-flight calls before dispatch; stop admitting work when spent plus reserved plus the next reservation exceeds the cap. ## Fields

- `review_id`: original stable review ID.
- `review_text`: original customer text.
- `review_rating`: original star rating, 1–5; not an assigned severity label.
- `review_likes`: helpful-vote count in the source snapshot.
- `app_version`: source app-version string; often missing.
- `review_timestamp`: original timestamp; timezone unspecified.

The full extract has 13 empty review texts, 159,701 missing app versions, and no repeated review IDs. All these rows remain in the full CSV. Samples use unique nonempty reviews with valid ratings. The 100-review cost pilot is the first 100 rows of the 500-review checkpoint, which is a subset of the 10,000-review development checkpoint; the golden 50 is disjoint from all three. Sample order is determined by SHA-256 with the fixed seed recorded in `manifest.json`.

## Limits

This is a historical snapshot of self-selected public app reviews. It contains no account revenue, plan tier, confirmed churn, or complete customer population. Missing versions and unclear or unsupported-language text need explicit handling. A review expressing cancellation intent does not prove that cancellation happened. The final analysis covers the full corpus; report incomplete classifications and their effect on conclusions. Do not include synthetic evaluation cases in business results.
